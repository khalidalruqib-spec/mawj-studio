## Template JSON structure (reference)

Every template follows the canonical `VideoTemplate` type in  
`src/lib/video-template-engine.ts`. Key fields:

```
id, name, category, aspectRatio (9:16), width (1080), height (1920),
duration (sum of all scene durations),
safeMargins { top:160, bottom:260, left:70, right:70 },
requiredInputs [ { key, label, type, default, required } ],
scenes [ { id, name, start, duration, background, transition, layers[] } ],
audio { music: null, volume: 1 },
export { format:"mp4", fps:30, quality:"1080p" }
```

Layer types used: `text`, `image`, `video`, `shape`, `captions`  
Animation types: `fadeIn`, `blurReveal`, `slideUp`, `slideLeft`, `slideRight`, `slideDown`, `pop`, `bounce`, `zoomIn`, `typewriter`

### 3. Caption layer rendering
The 6 caption-style templates all use `type: "captions"` layers with `source: "auto"`.  
The browser renderer in `src/lib/browser-template-renderer.ts` currently calls
`drawTextLayer()` for captions — it should render a placeholder when no transcript
is loaded (e.g., a frosted rect with "[ captions appear here ]" text).

### 4. `typewriter` animation
`captions-typewriter` uses `animationIn: { type: "typewriter" }` on text layers.  
The renderer has a `typewriter` case in `getLayerTransform()` — confirm it renders
character-by-character or at least a graceful fade-in as fallback.

### 5. Template preview in browser
All 16 templates have `thumbnail.svg` + `preview.svg` generated by  
`scripts/gen_templates.py`. The asset API (`/api/templates/[id]/asset`) already
falls back from `.png` → `.svg`, so these will display in the template browser  
without any additional changes.
